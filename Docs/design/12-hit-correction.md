# 히트 보정 (타격감)

## 왜 필요했나
무기 궤적으로만 판정하면 위치가 조금만 어긋나도 "맞은 것 같은데 안 맞는" 느낌이 자주 났습니다. 상용 액션 게임은 대부분 판정을 관대하게 보정합니다.

## 무엇을 설계했나
1차로 정밀 판정을 쓰되, 빗나갔을 때 **"이 정도면 맞은 것"** 으로 보정하는 2차 판정을 추가했습니다.

## 어떻게 설계했나
매 프레임 **두 번 스윕**합니다 — 이전 프레임 칼끝 → 현재 칼끝(궤적, 프레임 사이 관통 방지)과 칼 뿌리 → 칼끝(칼 전체)을 각각 스피어 스윕해, 빠른 스윙에서도 새지 않고 칼끝보다 가까이 붙은 적도 잡습니다. 그래도 스윙 내내 아무도 못 맞히면, 공격자가 **정면 원뿔 + 사거리 안**에서 바라보는 대상에 보정 히트를 넣습니다(소프트 락온의 `AcquireTargetEnemy`를 재사용). 뒤/멀리 있는 대상은 원뿔·거리로 걸러 막 꽂히지 않도록 하고, 죽은 대상(`IsDead`)은 제외합니다.

보정 히트도 **동일한 히트 이벤트(`Event.Attack.Hit`)** 를 쏘므로, 적의 확률 회피 등 이후 로직이 그대로 적용됩니다. 다만 보정 히트의 이벤트에는 `HitResult`(타격 지점·법선) 없이 `Target`만 실립니다 — `OnHitEvent`가 `Target`만 읽으므로 문제없지만, 히트 위치가 필요한 소비자는 근접 경로와 구분해야 합니다.

```cpp
// 매 프레임 두 번 스윕 (터널링 + 근접 누락 방지)
SweepInto(PrevSocketTip,  CurrSocketTip);   // ① 칼끝 궤적
SweepInto(CurrSocketRoot, CurrSocketTip);   // ② 칼 전체

// 스윙 종료, 아무도 못 맞힘 → 정면 대상에 보정 히트
void UWeaponAnimNotifyState::NotifyEnd(...)
{
    if (bUseFallbackHit && HitActors.Num() == 0)
        TryFallbackHit(MeshComp);   // AcquireTargetEnemy + (사거리 & 정면 원뿔) 게이트, 죽은 적 제외
}
```

**왜 폴백을 같은 이벤트로 쐈나** — 보정 히트를 위해 별도 데미지 경로를 만들면 회피·그로기·게이지 로직을 또 복제해야 합니다. 정상 판정과 똑같은 `Event.Attack.Hit`를 쏘면, "관대하게 잡아준다"만 추가되고 그 뒤 처리는 전부 기존 파이프라인이 담당합니다. 원뿔·거리 게이트는 "관대함"이 "부정확함"으로 넘어가지 않게 막는 안전장치입니다.

> 이 문서는 이미 별도로 정리한 **피격 판정 설계**를 보완하는 "타격감" 관점의 기록입니다.
